# Halqa Follow-up — متابعة الحلقة

مشروع مستقل لمتابعة الحلقات القرآنية، مبني للجوال بالعربية وRTL. لا يوجد ربط بمنصة إحياء. التصميم المرجعي: https://www.figma.com/design/r6ZL46yQpD0mAlJwZYbNgw?node-id=1-64

## التشغيل المحلي

يتطلب Node.js 24، PostgreSQL 17 أو أحدث، ومتصفح Chromium لتوليد PDF.

```sh
npm ci
cp .env.example .env
# عدّل DATABASE_URL وAPP_URL وAUTH_SECRET وSEED_TEACHER_CODE في .env
# يمكن تشغيل PostgreSQL المحلي عبر:
docker compose up -d
npm run db:migrate
npm run db:seed
npx playwright install chromium
npm run dev
```

`AUTH_SECRET` سر عشوائي بطول 32 محرفًا على الأقل. يمكن توليده بواسطة `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"`. اختر رمز seed عشوائيًا من ستة أرقام؛ لا يوجد رمز افتراضي. seed يضيف معلمًا، حلقة، ستة طلاب وواجب اليوم، ولا يطبع الرمز. إعادة تشغيله لا تستبدل البيانات أو الرموز الموجودة. استخدمه لبيئة التجربة فقط، ولا تنشر بيانات التجربة كبيانات تشغيل حقيقية.

افتح http://localhost:3000 وأدخل الرمز الذي وضعته. إذا ارتبط المعلم بأكثر من حلقة تظهر شاشة اختيار الحلقة. الملفات السرية غير متتبعة في Git.

## تدفق المعلم

- تعرض قائمة الطلاب النتيجة اليومية والتقدم في اعتماد النتائج.
- لكل تسميع إدخال مستقل للحفظ أو المراجعة؛ يمكن تكراره خلال اليوم. النتيجة اليومية منفصلة: حفظ / لم يحفظ / غائب فقط.
- واجب اليوم يملأ حقول الحفظ والمراجعة فعليًا عند فتح نموذج التسميع. يستطيع المعلم تعديل المدى قبل الحفظ. حفظ المنجز لا يغير المطلوب.
- واجب الغد مستقل بتاريخ الاستحقاق، ويظهر تلقائيًا في اليوم التالي دون مهمة مجدولة. اسم الصورة نص فقط.
- يمكن إلغاء الغياب؛ يعود الطالب إلى انتظار النتيجة. نقل الواجب ينسخ المطلوب إلى الغد مع حفظ مصدره، ولا يستبدل واجب غد موجودًا. إلغاء الغياب لا يحذف الواجب المنقول حتى لا تضيع تعديلات المعلم.
- الغياب يُرفض إن وجد تسميع فعلي اليوم. يمكن اختيار «لم يحفظ» مع الاحتفاظ بتفاصيل التسميع الفعلية.
- لا ينتهي اليوم إن بقي طالب بلا نتيجة. بعد الإنهاء تصبح البيانات للقراءة والتقرير فقط.
- PDF فردي أو للحلقة، صفحة A4 مستقلة لكل طالب، يتضمن الحالة والتسميع الفعلي وواجب الغد والملاحظات واسم الصورة. يشترط وجود نتيجة لكل طالب مشمول بالتقرير. يستخدم Cairo محليًا ولا يرسل بيانات الطلاب لخدمة خارجية. يتكيف حجم المحتوى ليتسع في صفحة واحدة عند كثرة التسميع.

## البيانات والحسابات

`Teacher → Halqa → Enrollment → Student`، و`DailySession → DailyStudentStatus → RecitationEntry`، بينما `Assignment` مستقل عن التسميع. علاقة التسجيل والجلسة المركبة تمنع ربط نتيجة طالب بحلقة أخرى. النتيجة nullable إلى حين اعتمادها؛ لا توجد حالة جزئية.

المدى هو سورة/آية البداية والنهاية. يوجد تحقق مشترك في الواجهة والخادم لجميع السور الـ114، وقيود PostgreSQL إضافية على التسميع. مرجع حدود الآيات: [Tanzil Quran metadata](https://tanzil.net/docs/Quran_Metadata).

المقادير والإجماليات الآن بالصفحات، وفق خريطة محلية للمصحف المدني 604 صفحة تغطي 6236 آية. أجزاء الصفحة تقريب هندسي مبني على إحداثيات الكلمات في السطور، وليست نسبًا رسمية لكل آية. [تعريف الحساب ومصدره وإصداره وحدوده](docs/madani-pages.md). يحفظ التسميع الجديد المقدار وإصدار الخريطة معًا، وتحسب السجلات السابقة عند العرض دون تعديل الأيام المغلقة. تتكرر المقادير بتكرار التسميع لأنها نشاط مسجل، وتبقى الواجبات مستقلة عن المنجز. لا يوجد إدخال صفحات يدوي.

## الأمان والنشر لاحقًا

- فهرس الرمز HMAC بمفتاح سري، والتحقق بواسطة scrypt مع salt مستقل. لا يُخزن الرمز الصريح. تغيير `AUTH_SECRET` يتطلب إعادة إصدار الرموز.
- جلسة برمز عشوائي 256-bit؛ لا تحفظ قاعدة البيانات إلا SHA-256 منه. Cookie من نوع HttpOnly وSameSite=Lax وSecure في الإنتاج. «تذكرني» لمدة 30 يومًا، والجلسة المؤقتة دون cookie دائم ولمدة 12 ساعة بالخادم. الخروج يلغي الجلسة بالخادم.
- تحديد محاولات الدخول في PostgreSQL بحسب الرمز والعميل وإجمالًا، ويعمل عبر عدة نسخ من التطبيق. لا تُستخدم ذاكرة العملية وحدها.
- فحص Origin لكل كتابة؛ اضبط `APP_URL` إلى الأصل الصحيح. تحقق ملكية الحلقة في القراءة والكتابة والتقارير. PDF محدود المعدل والتزامن.
- استخدم HTTPS على `reports.alrahmakuran.site` واضبط `APP_URL=https://reports.alrahmakuran.site`. لا يوجد نشر أو تغيير DNS في هذا الفرع.
- اترك `TRUST_PROXY=false` إلا خلف proxy موثوق يستبدل `X-Forwarded-For`؛ حينئذ اضبطه true. دون proxy موثوق تكون حصة العميل مشتركة لتجنب تزوير عنوانه.
- اضبط `APP_TIMEZONE` إلى توقيت المؤسسة؛ الافتراضي Europe/Istanbul. تحفظ الأيام كتاريخ مؤسسة مستقل عن توقيت خادم التشغيل.
- التطبيق يحتاج تشغيل Node.js وPostgreSQL، وليس static export. ثبّت Chromium في بيئة الخادم؛ على Linux: `npx playwright install --with-deps chromium`. تأكد من تضمين `public/fonts`، ومن قدرة الخادم على إطلاق متصفح headless. احتفظ بنسخ احتياطية لقاعدة البيانات.

## التحقق

```sh
npm run lint
npm run typecheck
npm test
npm run build
# اختبار التكامل على قاعدة اختبار معزولة فقط:
TEST_DATABASE_URL="postgresql://.../halqa_test" npm test
```

اختبار التكامل ينشئ سجلات اختبار خاصة به ثم ينظفها. يغطي تعدد التسميع، منع التكرار، حدود الآيات، فصل المطلوب عن المنجز، انتقال واجب الغد، الغياب وإلغاءه، عزل الحلقات ومنع التعديل بعد الإغلاق. GitHub Actions يشغل PostgreSQL والفحوص نفسها.
